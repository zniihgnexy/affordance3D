# 几何交互理解：调研与 Pipeline v1

**状态：研究讨论稿；2026-10-28**  
**性质：候选研究设计，并非已实现或已证明具有新颖性的系统。** 本文件回应项目负责人对 understanding block 的进一步说明，不修改《项目总控》。此前以放置规则和重观察为中心的草案应视为早期候选；本稿更准确地体现以局部几何交互学习为核心的设想。

## 1. 对研究想法的理解

局部几何是理解交互的基本单元，但一个局部 patch 并不对应固定的动作标签。交互取决于多个局部区域的几何关系、场景状态、意图、施力或运动方式，以及执行者能力。理解模块应从视频与交互经验中学习这些关系，而不是单纯把物体或框映射到一个预设技能。

期望模块具备：

1. 将多帧观察积累成可更新的 3D 场景记忆；
2. 学习局部区域以及区域与区域间的关系，并把它们和交互后的变化联系起来；
3. 对不同意图产生不同的关联理解，输出可供策略使用的连续潜在特征；
4. 下游可选择通过 adapter 连接 VLA、其他连续动作策略，或用可解释探针/文本表达；不把文本作为唯一中介。

局部几何是核心归纳偏置，不要求把整个场景拆成预先命名的几何类别，也不排斥在确定目标、语言理解或物理推断时使用语义。以下从 RGB-D 视频及已知相机位姿开始，逐步研究更难的输入。

**综合判断：** 这个方向有明确技术基础，但竞争活跃。候选创新问题应聚焦在一个可验证的窄问题上，例如：**局部几何交互经验能否以可更新的时序 3D 表征，跨对象—环境组合及不同目标复用，同时支持连续行动决策？** 目前仅是研究假设，需要逐篇核对数据、模型与实验，不能视为已经证明的空白。

## 3. 总体架构：从观察到交互理解

```text
         时间连续 RGB-D + 相机位姿 + 机器人可观察状态
                              │
               多视图融合 / 时序跟踪
                              │
           M_t：带可见性和时间信息的 3D 记忆
                              │
     局部几何 token + 邻域/物体间关系 + 全局上下文
                              │
            意图查询 g ───→ 几何交互理解块
                              │
          Z_t,g：连续交互表征（不必是人类可读标签）
                ┌─────────────┼──────────────┐
           后果预测       连续动作策略       可解释探针
       可能变化/置信度   adapter / VLA       区域/运动/文本
                └─────────────┴──────────────┘
                              │
          新观测、接触与结果 → 更新记忆和训练数据
```

### 3.1 记忆与局部几何

第一版用相机位姿将 RGB-D 融合成带时间戳的点云/体素记忆，区分已观察表面、自由区域和未知区域；保留可见性、最近观测时间、局部动态变化等。点云中的局部邻域作为 token，编码相对坐标、尺度、法线或由网络学习的特征。通过距离、相对姿态和注意力聚合邻域与更大范围上下文，让模型知道局部区域周围还有什么。

不要求输入类别标签或人工框。第一版可通过人工指定点、目标区域或自动生成的类别无关追踪获得指向；若使用模拟真值分割，只能作为训练信号/诊断或明确标记的 oracle。类无关分割、聚类、3D 跟踪和 RGB 特征是可替换的技术选择，并非已经解决的前提。局部和全局信息都必要：只看一小块平面，无法知道目标尺寸、远处障碍或机器人的可达范围。

### 3.2 意图不等于动作标签

记 `g` 为希望实现的**效果**，而非固定轨迹。可由：

- 指定几何目标：相对位置/目标区域或可观察目标点云（首版优先）；
- 目标状态或短示范片段：用编码器形成目标条件；
- 自然语言：通过外部视觉语言 grounding 投影为目标条件；这种映射可能模糊，需单独评估。

例如相同长条物与周围障碍，目标可以是“把物体移到左侧”或“通过狭窄通道”。理解块应随目标改变其关注区域和潜在交互，而不是只知道类别。训练中允许通过事后实现的状态构造目标，但测试时目标必须在行动前给定；避免将未来观测泄漏到推理输入。现实中语言和目标对象选择不可凭纯几何自动解决。

### 3.3 对理解块的功能定义

一个研究原型可以写成：

- `Z = U(M_t, g)`：按意图读取时序几何记忆得到交互表征。
- `p(ΔM, contact, collision | M_t, a, e)`：给定候选短时动作 `a` 和机器人可观测状态/本体信息 `e`，预测可观察变化及不确定性；不一定全部显式输出，也可用可查询 probe 评估。
- `p(a | Z, e)`：生成多种连续候选动作或短轨迹；它是实现路径之一，不是固定动作表。可用小型生成模型、diffusion policy 或先用简单候选采样验证。

**意图 g 指目标；动作 a 指具体的试探方式；两者不同。** 理解块提供候选的关系和变化先验，不承诺它独自解决完整规划或闭环控制。仅训练 `p(a | M, g)` 可能学到模仿快捷方式；仅做几何重建也不保证表示会包含交互知识。需比较动作条件后果学习是否带来额外收益。

### 3.4 两条下游接口

- **连续特征接口：** 冻结或微调理解块，将局部/关系 token 经过 adapter 或 cross-attention 输入现有策略。先用小型连续策略证明可用，再选择有可用代码和硬件支持的 VLA；需要机器人轨迹监督或其他动作对齐，不能假定接入后自然会控制。
- **可解释接口：** 可视化相关区域、预测运动、碰撞风险及不确定度，再探索生成文字。文字须基于可核验的模型输出和观测；流畅解释不等于真实因果解释。两种接口须共享或明确对照，不能因为换了接口就把差异直接归因于理解块。

## 4. 训练数据和监督从哪里来

### A. 观测与几何预训练

采集随相机移动的 RGB-D 多视角帧、相机内外参及机器人可观测状态。对可见局部几何做跨视角一致性、可见区域重建或匹配；仅在有效深度区域计算损失。隐含目标是编码局部形状和关系，不保证物理交互能力。位姿与尺度变换测试中，重力方向及物理条件必须一起正确处理，不能将任意旋转都当作物理等价。

### B. 模拟交互与因果对照

在相同初始场景上采样不同连续接触位置、末端姿态与短程移动方向/距离，执行并记录结果：时序 RGB-D、已执行动作、变化后的可见几何、碰撞/接触与结束状态；记录成功也记录失败。把动作与后果配对，学习预测、排序或多模态后果分布。尽量构造同一物体/相同几何但环境布局或意图不同的配对，测量邻域关系和目标条件是否被使用。

无人工 bbox 或语义标签不代表没有监督：仿真器自动状态、接触、任务效果、执行动作和前后观察都是训练或评估信号。每个实验须标明哪种监督被使用，以及哪些仿真特权信息仅用于训练标签或 oracle。自动采样本身也受初始分布与行动空间限制；失败不必然说明目标不可能，可能只是动作没找到、不可达或观测不足。

### C. 目标条件学习

先对每次 rollout 以其后续可观察结果做 hindsight 目标构造，并保留原始动作及失败；采样匹配与不匹配目标，防止模型忽略 g。真实任务测试要使用独立生成或指定的目标，包括不可行目标。不应把所有 hindsight 样本都当作原始任务的成功。后续加入少量演示或语言—目标对齐，明确标注额外监督和数据成本。

### D. 联合或分阶段学习

首选先训练几何编码器和后果预测器，再冻结理解块训练轻量策略；随后对比联合微调。候选损失：可见 3D 几何/运动预测、行为结果和碰撞预测、目标匹配、可选局部关系一致性。每项应单独消融，避免以复杂总损失堆叠代替可检验的机制。对多模态结果应预测分布或多个候选，避免均值预测不可能的动作；负样本和不平衡采样比例需要记录。

## 5. 首个实验：移动物体，比较不同目标与环境

**推荐候选而非最终锁定：** 在可控桌面上用一个机械臂移动刚体。对同一对象和局部接触几何，改变障碍布置及连续目标位置；场景中包含开放区域和窄通道。第一轮只要求短时单接触推动，使用多视角 RGB-D、已知相机位姿；机器人状态和动作由同一接口提供。后续再加入抓取、放置和关节物体，确保研究不是被“推”这个标签定义。

关键成对试验：

1. **同物体、同环境、不同目标：** 交互特征和行动候选是否随目标变化？
2. **同物体、同目标、不同障碍：** 模型是否理解对象—环境关系，而非仅记住对象局部？
3. **新物体局部几何或新组合：** 在未见对象与场景组合下效果如何？
4. **短期遮挡：** 融合历史和当前帧相比如何？几何变化被/未被观察时是否恰当体现不确定性？
5. **相同外观但不同摩擦等属性：** 纯视觉模型应保持不确定，试探性动作能否帮助更新？这属于扩展实验。

注意：目标选择、运动参数化、仿真器动力学和机器人能力在此都是具体假设，形成一个可检验的起点，不是对最终理论范围的限制。

## 6. 评测：证明学到交互，而非记住标签

**主要对照，逐项增加信息或训练：**

- 当前帧点云 + 目标条件的相同容量策略；
- 多帧几何记忆 + 目标条件，无交互预训练；
- 几何预训练 + 相同策略；
- 局部几何 + 交互后果预训练；
- 加物体—环境关系；
- 加时序记忆与可见性信息的完整模型；
- 打乱 token、随机初始化/冻结编码器和真值 oracle 等诊断。

在兼容任务设置时再对照 O2O-Afford、ActAIM 或相关公开方法；如无法按同等输入重新实现，应明确差别，不直接比较论文指标。保持相同观测、目标、机器人、轨迹量、训练预算、策略头与评测规则；必要时分开比较参数量/算力。

**主要指标：** 达成独立给定目标的成功率与目标几何误差、碰撞率、可行行动的召回和效率；对候选动作后果的预测误差、负样本区分与概率校准；在遮挡、记忆过期及目标切换下的表现。汇报多随机种子、场景级试验数及置信区间，检查不同交互模式的覆盖率，不只测最容易的一种。

按对象资产家族、场景布局、相机轨迹和意图组合预先划分训练/验证/测试，不能按视频帧随机划分。分别报告未见实例、未见几何族、未见对象—环境组合，以及未见目标组合；不能把未见类别等同于未见几何。控制外观、位置、接触频率等捷径，设计同几何不同物理属性的反事实组。评估 VLA 增益时还要做同一 VLA、同预算、特征消融与任务成功对照。

## 7. 可行性、边界与实施顺序

- **可行的原因：** RGB-D、仿真交互、局部点云表示、连续策略和后果预测都有现有技术路径；无需从零训练大型 VLA。
- **物理不可辨识：** 相同外观和几何可能对应不同质量、摩擦、固定方式或刚度；静态 RGB-D 不能唯一识别这些。预测是“基于观察和经验的可能性”，需概率表示、额外观测或交互试探，不可声称已经知道全部物理可行性。
- **开放动作的现实约束：** 用连续动作减少对人工技能标签的依赖，但训练与评测仍有限定本体、可采样动作、场景和物理范围；不能宣称无限制的动作空间。
- **记忆可辨识：** 未观察到的环境变化无法凭旧视频确定；应标记未知或复查。重观察只是可选能力，不是唯一研究主线。
- **数据成本：** 随机接触往往产生大量无效样本；混合启发式采样、探索和失败记录，并和对照统一数据预算。仿真到真实的材料、感知和接触差异需要独立实验。
- **机器与平台：** [ManiSkill 3](https://github.com/mani-skill/ManiSkill) 支持 RGB-D 与多种机器人仿真，是候选平台；官方 [安装说明](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/installation.html) 显示无显示器渲染仍需合适 GPU/Vulkan，Linux/NVIDIA 支持较好，Windows GPU 仿真支持受限。学校 SSH 环境的 GPU、显存、驱动及渲染许可、5060 设备系统/显存均未验证。

阶段 0：确认训练 GPU/驱动与本地平台，做一个 RGB-D + 相机位姿 + 重复回放的最小验证。  
阶段 1：用少量场景采集多目标的短时交互，建立当前帧和多帧基线，确认动作与结果记录可靠。  
阶段 2：训练局部几何及动作条件后果模型，用目标切换和场景反事实做验证。  
阶段 3：引入记忆、遮挡和跨对象组合，做消融及泛化测试。  
阶段 4：先接轻量连续策略，再在资源允许且基线稳定时接 VLA adapter；文本解释单独验证。

每阶段若发现训练信号不足或几何效果被简单基线解释，应先修正数据与任务，再扩大模型。此文档为设计，未安装平台、生成数据、运行实验或验证算力。

## 8. 下一次讨论建议

1. 意图首版选择目标相对位姿、目标观察/示范还是语言？建议先用前两者之一，避免语言 grounding 主导核心实验。
2. 首轮以短时推动为可控实验是否符合研究兴趣？这不排除后续抓取、放置、工具使用和 articulated 物体。
3. 希望最终更强调提出一种可迁移的理解表征，还是证明它显著提升某类现有 VLA？这会影响核心 baseline 和数据预算。
