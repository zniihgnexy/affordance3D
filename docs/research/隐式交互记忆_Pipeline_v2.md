## 1. 研究目标与边界

本版本以**可训练的隐式交互记忆**为核心，直接针对机器人动作所需的场景和交互信息设计。训练时可以利用显式几何、仿真状态和交互结果；运行时记忆主要由可学习的 tokens/slots 组成，不要求生成可查询的对象图或场景地图。局部几何关系是基本研究单元，但不把它强制映射为固定物体类别或动作标签。

第一版部署假设仍是**RGB-D、相机内参与已知位姿、机器人自身状态**。模型可以将深度转换成当前帧的局部 3D 输入，这与“没有显式持久地图”不同；不能称为纯 RGB 推理。可以另行设计以 RGB-only 为输入、几何仅用于训练的学生模型，但需要额外验证并按其真实推理输入报告。

**研究问题：** 在相同视频、机器人动作与任务数据下，能否通过局部机器人—物体—环境几何关系及实际交互结果，训练一种时序隐式记忆，使其在遮挡、意图变化和未见物体—环境组合中，比等预算的普通隐式记忆更能预测交互后果并改善同一机器人策略？

这是一项可否定的假设。3D 教师→隐式 memory→VLA 已有 [GeoMem-VLA](https://arxiv.org/abs/2610.29866)，动作—结果写入已有 [MemBodied](https://arxiv.org/abs/2609.28256)，相似的 memory/prediction/action 也有 [UniMPA](https://arxiv.org/abs/2609.11875)。因此此图和公式是**待验证的设计，不是已确立的论文贡献**。

## 2. 输入与因果时序

每个时刻可用输入：

\[
o_t=(I_t,D_t,K,T_t),\quad s_t=\text{可观测机器人本体状态},\quad g_t=\text{语言或目标状态}.
\]

其中 \(T_t\) 为约定坐标系下的已知相机位姿。机器人已执行的动作 \(a_{t-1}\) 可进入当前记忆更新，但候选或未来动作的真实结果不可用。

严格顺序：

1. 机器人已实际执行 \(a_{t-1}\)，获得当前观察 \(o_t\)；
2. 利用 \(o_{\le t}\)、\(a_{<t}\) 更新记忆；
3. 用当前目标读取记忆并产生 \(a_t\)；
4. 执行 \(a_t\)，等收到 \(o_{t+1}\) 才能把实际结果写入。

训练的未来帧、仿真对象位姿、接触/碰撞或成功标签只计算监督，不得作为时刻 \(t\) 的前向输入或记忆写入。候选动作只进入**结果预测头**；不应要求 VLA 在生成动作之前先知道将要生成的动作。反事实候选的预测不能当作实际发生的事件写入真实记忆。

## 3. 核心算法：构建隐式交互记忆

### 3.1 局部几何 atom：由观测生成关系 tokens

对有效深度与 RGB 形成当前帧的可见局部 3D 点/patch。根据局部邻域采样得到特征 \(h_{i,t}\) 及位置 \(x_{i,t}\)；这不是人工命名物体，也不需要手工 bounding box。将相对位置和局部特征汇合成关系 token：

\[
r_{i,t}=\sum_{j\in \mathcal N(i)}\alpha_{ij}\,
\phi_{\theta}\!\big(h_{i,t},h_{j,t},x_{j,t}-x_{i,t},\|x_{j,t}-x_{i,t}\|\big).
\]

\(\mathcal N(i)\) 是多尺度局部邻域，\(\alpha_{ij}\) 是可训练的聚合权重。位置与方向在约定坐标系表达；全局/较大邻域上下文保留以处理局部 patch 看不到的物体尺寸、障碍和可达条件。若需要机器人—环境关系，可将机器人本体状态或可获得的机器人几何加入编码；不假定视觉一定能自动分离机器人与对象。

**可实现的初版：** 对当前深度生成点云，采样少量 patch，用轻量 PointNet/MLP 编码局部几何，再由邻域 attention 构造 \(r_t\)。明确是否还输入 RGB 纹理；无类别标签不代表完全没有视觉语义。跨帧对应和局部遮挡可能失败，必须输出/携带有效性，不将错误对应视为已知事实。公式只是候选特征机制，并不保证旋转等变性、真实接触或物理可行性。

### 3.2 双流 slots：记状态，也记已发生的事件

**状态记忆 \(S_t\)** 用固定数量的可学习 slots，记住截至当前的局部场景与观察历史：

\[
S_t=U_S(S_{t-1},r_t,\nu_t),
\]

\(\nu_t\) 表示有效深度、可见性或对应可靠性信息；它必须由可用传感器和当前/过去观察估计，不能从测试真值获得。\(U_S\) 可先用标准 cross-attention 与残差更新。遮挡处没有观测证据时应该保留/标记历史，不能推断旧状态必然仍然成立。

**交互事件记忆 \(E_t\)** 保存已执行动作及其后可观察到的变化：

\[
e_t=F_E(r_{t-1},a_{t-1},r_t,s_{t-1},s_t,\nu_t),\quad
E_t=U_E(E_{t-1},e_t,\nu_t).
\]

例如，在第 \(t-1\) 帧尝试推一个物体，在第 \(t\) 帧看到它移动或受阻，事件特征可表示这段实际发生的关系变化。如果没有前一真实动作，或关键结果不可见，使用空事件/有效性标记，不把模型预测当作事实。

首版使用简单注意力写入。**候选增强：** 以可见区域中的“上一时刻预测的特征变化”与“当前真实观察编码”的差作为写入门控信号；预测是在过去时刻形成，误差必须仅在当下有效观测区域计算。遮挡、缺失和大残差不是动作失败的同义词。门控能否提高记忆使用效率须独立消融；[MemBodied](https://arxiv.org/abs/2609.28256) 已有动作—后果写入，不应把事后写入本身当作创新。

**原型尺寸仅为起始建议：** 状态 32 个、事件 16 个 slots、维度 128、局部邻域大小和深度由 pilot 确定；按 fp32 粗算 slots 本身约 24 KiB/episode，不含编码器激活、缓存和训练开销。数量不是已验证的最优值，须做预算/性能曲线。保持事件与状态两流不是理论必需，需对照单流且总 token 数相同的模型。

### 3.3 条件读取与机器人动作

利用任务目标、当前机器人状态查询两组隐式记忆：

\[
z_t=\operatorname{Read}_{\theta}(S_t,E_t,g_t,s_t).
\]

\(g_t\) 可以是目标状态/短演示，或来自语言编码器的意图向量。首个仿真实验可先使用低歧义的几何目标，同时保留语言接口；语言如何指定对象和关系需要独立验证。读取可采用 cross-attention；slot 不应被硬编码成固定动作类别。不同意图切换时可复用同一历史记忆。

将 \(z_t\) 经 adapter 投影到策略接口，使用同一机器人观测和状态输出动作块：

\[
\hat a_{t:t+H-1}\sim\pi_{\phi}(o_t,s_t,g_t,\operatorname{Adapter}(z_t)).
\]

先选择一个有可访问训练代码的预训练 VLA，固定 backbone/action expert、训练 memory encoder 和 adapter；动作损失仍可通过冻结网络反向传播到 adapter。若模型结构不支持外部 token，需修改 action expert/cross-attention 并测试，不能宣称零训练即可即插即用。之后再比较 LoRA 或少量微调，但需与相同参数量的 VLA 基线做对照。

动作表示完全遵循选定控制器：如末端相对位姿增量和夹爪目标，或绝对末端位姿；坐标系、尺度、控制频率、时间同步和夹爪定义必须显式记录。不同 benchmark（MIKASA vs RoboMME）的约定不相同，不能直接互换。语言可选，不强制把 tokens 转成文本。动作执行由仿真器/机器人控制器处理。

## 4. 训练目标和标签：从具体监督到机器人动作

训练数据的一个窗口包含 \((o_{0:t},s_{0:t},a_{0:t-1},g_t)\)，以及只供训练/评估使用的后续标签。按 episode 建立时间窗口，正确重置记忆，必要时使用 truncated BPTT；跨窗口保留状态时不能把验证或测试片段混入训练。

### 4.1 局部几何监督

从已观察区域采样局部关系查询点对 \((i,j)\)，由有效深度或者**明确标记的仿真真值**构造相对距离和方向标签 \(y^G_{ij}\)；点对是局部查询而非强制语义类别。给相同输入的 memory 训练辅助解码器：

\[
\mathcal L_{geo}=\frac{1}{|\mathcal V|}\sum_{(i,j)\in\mathcal V}
\left\|D_G(S_t,i,j)-y^G_{ij}\right\|_1.
\]

\(\mathcal V\) 仅包含已验证的有效监督；点索引和坐标的 query 如何对齐隐式 slots 需实现验证。若利用完整仿真几何或 mask 作为训练标签，要记录这是训练特权监督；无人工类别标签不等于无额外监督。该辅助任务可能过于容易或只学到静态几何，需要测它对后续效果的增量。

### 4.2 交互后果监督

给定历史记忆、目标和一个候选真实动作 \(a\)，预测执行之后的目标物运动、碰撞或任务结果：

\[
(\widehat{\Delta p},\widehat c,\widehat y)=
F_{\psi}(S_t,E_t,g_t,s_t,a).
\]

其中 \(\Delta p\) 表示约定坐标中的物体位移/局部状态变化，\(c\) 表示碰撞结果，\(y\) 是预定义任务是否达成。首版可用 Huber 位移损失和二元交叉熵；只在标签有效时计算，结果并非天然校准概率。对于真正多模态结果，可进一步试分布式预测或多候选，不能把确定性均值当成多模态模型。

不同候选可从**同一仿真快照分别恢复并执行**，形成配对干预：同样历史、不同实际动作与结果；这用于学习候选条件效应，未执行候选仍不能进入在线事件记忆。状态变化或对象位姿在模拟器里仅作标签，必要时另训练可从真实观察得到的替代标签。历史案例的成功、失败及接触都必须记录；一次失败不证明该目标物理上不可能。

### 4.3 机器人动作监督

使用机器人数据中的真实动作块及对应观察、意图训练 memory/adapter：

\[
\mathcal L=\lambda_G\mathcal L_{geo}+\lambda_E\mathcal L_{effect}+\lambda_A\mathcal L_{action}.
\]

\(\mathcal L_{action}\) 必须与选定策略一致：回归策略可用动作误差；flow/diffusion VLA 必须使用其原生动作训练目标，不可一律写作简单 MSE。三项权重和训练顺序通过验证集确定。真实动作标签的同步、单位和归一化需要验证；失败轨迹可训练后果头，不应不加区分地作为达成目标的行为克隆示范。动作学习需要机器人 embodiment 对齐的数据，普通人类视频不能直接当作目标机器人的关节动作。

## 5. 数据采集和最小可操作路线

### Stage 0：接口与数据质量

在 ManiSkill 自定义桌面场景，固定一个 Panda 类机械臂/控制器；校验 RGB-D、相机位姿、机器人 state、动作与仿真时间同步、目标位移和碰撞记录。简单虚拟推动器仅用于前期环境和标签调试，不得声称已经验证机器人可达性；尽早补机器人控制器和对应真实执行动作。环境/硬件适配尚未实测。

### Stage 1：先验证隐式记忆和交互预测

自建目标物、可移动障碍、短程推的可控几何场景；观察历史后局部遮挡，从同快照执行 K 个候选以产生监督。对照无历史、普通隐式历史和局部关系隐式记忆。pilot 先以少量场景、每场景约 4–8 个候选检查动作可执行、正负样本、同步和资源；这些是调试规模，不是发表结果或统计功效保证。按 pilot 调整正式数量与预算。

### Stage 2：检验事件记忆，避免只测试几何历史

第一阶段如果历史里只有“观察过障碍”，只能证明视觉/几何记忆有用，**不能证明事件记忆有用**。另设计成对轨迹：当前观测、目标、机器人状态尽量匹配，但之前执行过的动作/可观察后果不同，并导致后续候选的结果不同。可用遮挡后查询来隐藏影响信息；先用仿真逐对验证结果差异、观察不泄漏，再比较删除/交换事件记忆是否改变正确预测。不要让目标或者场景身份泄漏标签。未知的、从未被观察到的外部变化不能被凭空正确推断。

### Stage 3：尽早对齐机器人动作，再接现有 VLA

在相同场景收集机器人状态与动作轨迹。先做轻量行为克隆动作 head 的可行性测试，确认记忆 tokens 能影响机器人动作；然后复用预训练 VLA，训练 adapter/记忆并进行闭环仿真。SmolVLA 等候选需先检查模型接口、操作平台与可用显存，**未确定已可运行**。若基线 VLA 不支持深度，保持原 RGB 路径，并明确新的几何 memory 分支使用 RGB-D；提供同模态基线。

## 6. 对照与消融：确保所谓核心算法可被推翻

| 组别 | 历史与记忆 | 监督 / 目的 |
| --- | --- | --- |
| B0 | 只有当前帧 | 没有历史的能力；有意剥夺历史，不是同信息量比较 |
| B1 | 同样视频历史、普通单流 implicit tokens | 机器人动作与相同结果头，考察通常记忆 |
| B2 | 单流 implicit tokens + 几何监督 | 对照几何教师的额外作用 |
| B3 | 相同容量的 action–outcome 写入/普通事件记忆 | 近似 MemBodied 风格强对照，动作与几何训练预算可比；不能称为该论文复现除非逐项复现 |
| M | 局部几何关系 + 状态/事件隐式记忆 | 本研究待验证模型，按任务读取并对接同一动作 head |
| 显式参考 | 点云/地图或适配后的 SpatialMem 类记忆 | 方法诊断；按相同感知及预算适配，不直接套用 SpatialMem 原论文 QA 数字 |

必须进一步做 matched 消融：①相同总 slots 的单流 vs 双流；②有/无局部关系特征；③有/无几何关系监督；④有/无真实动作条件和后果监督（保留共享结果 head，监督量不同时明示）；⑤常规写入 vs 门控写入；⑥在动作推理时置空、打乱或替换记忆。加入同计算量的非几何辅助监督，区分监督内容和额外训练收益。预测/动作都应检测模型是否忽略 tokens 或依赖容易识别的场景 ID。

保持相同视觉/深度输入、轨迹量、目标、机器人 embodiment、action head、观测长度和评测预算；新增几何/碰撞真值是额外监督，不可能声称完全同监督，必须单列其标注/计算成本，并做数据效率曲线。

## 7. 评测问题、指标与合理的失败结论

- **局部几何：** 在已观察点对及遮挡后查询中测相对距离/方向预测，分别报告有效与未知区域。几何准确不等于 affordance 成功。
- **交互预测：** 同状态 K 候选的位移误差、碰撞/任务结果 PR-AUC、配对预测一致率；概率才使用校准/Brier，必要时风险—拒绝覆盖率。
- **记忆使用：** 遮挡前后，交换或清空历史；对先前交互后果不同、当前观察相近的配对测结果差异。单纯关注注意力可视化不证明因果使用。
- **机器人：** 同模型/数据的闭环成功率、碰撞及有效执行率，区分未见物体实例、几何族、环境组合和目标组合；按 episode/场景聚合、多个训练种子，报告置信区间和推理延迟/显存。多视角、感知和执行权限需一致。
- **外部 benchmark：** 后期 RoboMME 与 MIKASA 的官方协议应分别运行；MIKASA 官方 RGB-only，若方法依赖 RGB-D，要么先训练 RGB-only student，要么将额外模态单独报告，不能混为同一 leaderboard 设置。

若 M 只比 B0 好而不优于同历史的 B1/B3，不能声称局部关系算法有效；若 M 优势消失于控制监督量或新几何组合，不能宣称泛化。若输出动作未提升，说明交互预测收益未转化为控制；需调整动作接口或缩小贡献范围。大规模对照不可一开始全部运行，先以 pilot 验证数据和计算。

## 8. 与 SpatialMem 的关系及本版尚未解决的问题

SpatialMem 可作为显式、可查询记忆与 evidence retrieval 的基础和对照；v2 候选重点是训练时用机器人交互结果塑造隐式记忆，推理阶段让 tokens 直接影响 action expert。二者输入、任务和评测不同，只有统一数据和接口后才可作同任务比较。不能断言 SpatialMem 的结果由“显式”一个因素造成。

开放问题：

1. 局部几何要使用实时 RGB-D 还是训练期几何 teacher / RGB-only 推理？第一版采用前者，后者单独实验。
2. 当前 patch 采样和跨帧对应在缺失、动态和遮挡条件下是否足够可靠？
3. 事件 slots 与已有 MemBodied/UniMPA 等相比，局部关系和目标条件是否在公平设置中提供真正增益？
4. 几何目标、动作后果和策略损失是否互相促进，还是引入梯度冲突或额外计算成本？
5. 初期只验证推动；后续如何在抓取、放置、开关等不同 interaction 上检验复用？
6. 带已知相机位姿的仿真结果如何推广到真实视频的估计尺度与位姿？

## 9. 具体下一步

1. 核对目标机器的 GPU/系统、ManiSkill 最小渲染与相机坐标；选定一个动作数据格式和控制器。
2. 用最小场景采集一段 RGB-D + 真实机器人动作，逐帧可视化并检查对齐；从同一快照重复候选并验证标签。
3. 实现 B0、B1 与统一结果预测 head，再加入 \(S_t\) 局部关系；之后才加 \(E_t\) 事件流和 action head。
4. 先做“历史几何遮挡”与“历史交互后果”两个互补测试。通过后再接预训练 VLA adapter，并按 benchmark 的官方观测协议评测。

**这四步是计划，不是已经执行过的工程或训练结果。**
