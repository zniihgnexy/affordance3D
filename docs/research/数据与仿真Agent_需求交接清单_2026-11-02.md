# 给数据与仿真Agent的需求交接清单

**日期：2026-11-02｜当前讨论需求，用于调研筛选，不修改项目总控，不预先选定平台。**

## 1. 请围绕这个目标找资源

从连续、转换视角的观察视频中，构建并维护三维环境记忆（Environment Memory），保存对象、局部几何、可交互区域（Affordance）、时间与来源证据，供后续对象/关键帧/交互区域检索使用，未来连接机器人。

第一版可先围绕“哪里可以放下给定物体”（Placement / Support Affordance）设计实验；这只是便于筛选的优先任务，尚未锁定最终任务。不要求学习人类动作，不要求从头训练VLA或完成机器人底层控制。

## 2. 优先找什么样的环境和视频？

- **连续、多视角、可重访：** 相机能绕行、转头、离开后回看同一对象/区域；存在视角重叠、局部遮挡和解除遮挡。单张图或互不关联的短片只能作为子任务资源。
- **有可比较的局部几何：** 多种大小、形状、朝向的支撑面及可移动物体，能研究尺寸、空间余量和遮挡，不只靠“桌子/椅子”等类别猜功能。优先室内桌面及房间级场景。
- **有状态变化：** 可让物体移动、出现/移除，或使原本空闲的放置区域被占用、之后恢复；最好同时包含“变化过程可见”和“离开视野后变化”的情况。
- **不强制人类交互：** 变化可以由仿真脚本控制。用于记忆变化的重置/移动，不等于真实物理动作演示；若评价放置可行性，需另有碰撞/稳定性验证。
- **已有数据允许部分满足：** 静态多视角数据可验证空间融合，重复扫描可验证重访，动态序列可验证更新；请注明覆盖哪个子任务，不强求一套数据包办全部。

## 3. 输入与真值必须分开

**目标设置优先是RGB视频输入。** 但为调试和评价，优先寻找同时能提供下列辅助信息的资源；有这些信息不意味着模型可以全部读取。

| 信息 | 用途与权限 |
| --- | --- |
| RGB、时间戳、连续帧关系 | 主要观察输入；说明是否单目、同步多相机或预录片段 |
| 相机内参、深度、相机位姿 | 校准、RGB-D/已知位姿基线及几何评价；与RGB估计组分开，是否读取内参也须声明 |
| 实例分割、稳定实例ID、对象位姿 | 身份关联和变化评价；仿真ID不能直接提供给RGB方法 |
| 场景/物体几何、尺寸、碰撞模型 | 支撑面、空间余量、碰撞与放置条件评价；说明可否自动导出 |
| 遮挡/可见性证据及状态变化记录 | 区分没看见、被挡住与旧区域已空；说明标签定义，不能把引擎visible布尔量直接当完整像素真值 |
| 跨次扫描/重访的实例对应 | 评价同一物体的长期身份；说明是否真的覆盖移动后的对象 |

保留两个可分开的协议：**RGB＋估计几何**为目标条件；**RGB-D＋已知位姿**为首轮验证/诊断条件。当前总控已有后者作为起点，本清单不自动推翻它。机器人导航使用的地图/定位也须作为额外下游输入单列。

## 4. Affordance监督希望怎样获得？

- 最优先：有区域/点级标签，或可依据场景几何、目标物尺寸和仿真物理自动生成候选标签。
- 第一版重点区分：近似水平支撑面、物体是否放得下、候选空间是否被占用，以及仿真中的碰撞/稳定性结果。
- 请区分**几何候选区域、一次成功交互、完整affordance标签**；对象mask、动作类别或接触点不能直接替代全部可交互区域。
- 没有现成affordance标签也可推荐，但必须写明生成办法、额外标注工作与物理假设。RGB难以确定的摩擦/承重等，不能默认为已知。
- 有不同目标物尺寸、未见物体/类别和新场景划分更好；同一房间及其重扫尽量按环境整体划分，避免泄漏。

## 5. 平台最好能复现这些最小测试

| 测试 | 要验证的能力 |
| --- | --- |
| 换视角后再次看到同一表面 | 跨视角融合、区域一致性及来源帧检索 |
| 遮挡后回看，环境实际未变化 | 保留历史，不误删对象或交互区域 |
| 旧位置重新可见，物体确已移走 | 撤销过时位置；不要求猜出未观察到的新位置 |
| 原本可放置的表面被占用，随后清空 | 更新当前affordance，并保留过去证据 |
| 相似物体、新目标尺寸和新场景 | 实例区分、目标条件化及泛化 |

优先先做离线同视频比较，再接固定机器人/相机控制器。输出可以是对象、关键帧、候选交互区域与不确定性；不要求直接输出关节动作。具备机器人导航、抓放及执行验证接口属于后续加分项。

## 6. 请核实的实际运行条件

- 学校GPU通过SSH使用：核查无图形界面运行、离屏渲染及数据生成；GPU型号/显存/数量未知，不作默认假设。
- 另有NVIDIA 5060设备可用于仿真测试，但显存、系统和实际兼容性未确认；请报告版本要求、内存/显存及最低可运行配置，不能仅凭GPU名称保证能跑。
- 优先可脚本化控制相机、重置场景、调整物体状态、设置随机种子并导出帧和独立真值的资源。
- 分开报告训练、数据生成、推理和可视化成本；说明数据大小、下载权限、许可、资产依赖及维护状态。

> 名称及官方链接｜覆盖子任务｜视频/视角/重访能力｜状态变化能力｜可用标注与真值｜affordance监督或生成方法｜RGB权限划分｜实际运行要求｜数据/代码/资产访问与许可｜缺失项和补充成本｜推荐理由。

将“官网声称支持”“代码/数据入口可访问”“已下载”“实际跑通”分别标明，并附核查日期与原始来源。请给出一个最小组合建议：**一个可控仿真环境＋一套真实验证数据**，说明能支持哪些实验、还缺哪些条件。

本次以调研和方案为主；如需大规模下载、付费计算、安装重型依赖或更改远程环境，先报告具体资源与代价。
