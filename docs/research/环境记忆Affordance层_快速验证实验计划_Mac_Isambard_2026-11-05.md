## 1. 资源事实与首轮目标

用户补充：本周只有当前 Mac；后续可申请布里斯托 Isambard-AI，通过 SSH 训练，可视化保留在 Mac。

2026-11-05 只读硬件检查：Apple M1、16 GB 统一内存、arm64，工作区磁盘约余 44 GiB。当前命令行 Python 未检测到 torch、numpy 等实验依赖；这不代表其他独立 Python 环境均无依赖。MPS 须安装所需环境后实测，不承诺算子和模型直接可用。

首轮只回答三个问题：①像素／局部特征能否正确进入环境空间；②affordance 监督产生的特征，是否比同预算普通特征更适合定位和读取功能区域；③历史记忆是否保留当前视野之外但此前看见的证据。物理环境约束、动态状态维护、跨执行者迁移和 VLA 控制后续分别验证。

## 2. 数据选择与下载闸门

### 主数据：SceneFun3D 的 train/val 小子集

优先选一段含多个清晰功能部件、视角有重叠的扫描视频。开发用 1 个场景，另用 1 个不同场景作不调参的小检查；本周只采样每场景 40–80 帧，先 10–20 帧测速和排错。采样按时间和相机覆盖进行，不按测试标签挑最有利的视图；保留时间顺序。

[官方 downloader](https://scenefun3d.github.io/documentation/toolkit/data-downloader/)支持 custom visit_id/video_id 与资产选择。图像通常按序列包下载；几十帧的实验规模不是几十帧的网络下载规模。先查询实际压缩包大小与解压空间，记录数据版本、ID和清单，避免默认下载整个 split。

首选资产：laser_scan_5mm、crop_mask、annotations、descriptions、hires_wide、hires_wide_intrinsics、hires_depth、hires_poses。暂不取原始 MP4、额外视频、motions 或 ARKit mesh。

[官方资产定义](https://scenefun3d.github.io/documentation/dataset/file-structure/)说明：hires_depth 是 Faro mesh 渲染深度，hires_poses 是 Faro 坐标系的 COLMAP 估计位姿；这是便于排错的几何条件，不是实测 LiDAR 噪声条件。lowres_depth 为传感器深度，lowres_poses 在 ARKit 坐标系；混用会引入配准问题。首轮不混用两条路径。

首轮按有效观察建立稀疏表面记忆，不将完整 Faro 场景或测试功能 mask 当作模型已观察的输入。完整激光扫描及标注用于配准诊断和评价；E0 的 oracle 诊断例外需单列。

本地整体新增数据、模型和缓存先设 **8 GiB 预算上限**，这是资源控制建议，不是数据集实际大小。若单序列压缩及解压峰值超预算，SceneFun3D 直接放到远程处理，本地保留后续导出的少量样本及结果。

### 备用：UMD Part Affordance，限局部分支检查

[官方页面](https://users.umiacs.umd.edu/~fermulcm/affordance/part-affordance-dataset/index.html)列出 Tools 下载包约 2.9 GB、Cluttered Scenes 约 0.2 GB；这不是解压后体积。[README](https://users.umiacs.umd.edu/~fermulcm/affordance/part-affordance-dataset/README.txt)说明每三帧一张人工标签，其余自动标签不作为本轮独立真值。

若 SceneFun3D 本地获取代价过高，可先用 UMD 调试 RGB-D、功能 mask、轻量 head 和可视化。它不能代替带注册位姿的场景时序记忆验证，且工具 affordance 类别不能直接当作 SceneFun3D 的功能类别。

本轮不并行下载 EPIC、HOI4D、整套 AGD20K 或大型 AFUN 训练包。之后需要动态交互时，再依据缺少的监督补一种资源。

## 3. 本周 Mac 阶段

### E0：空间投影与数据链路

**问题：**图像、深度、相机内外参和标注坐标是否对齐？

- 输入：1 个场景、10–20 帧起步，检查后扩至40–80帧。
- 操作：读取匹配时间的 RGB-D 和位姿；彩色点云；核查功能部位与空间位置；查看同一部位的多个观察。
- 诊断允许用 GT mask 绘制和传播以隔离几何错误，所有输出标注 oracle；这不算 affordance 学习实验。
- 检查约20处跨帧可见对应，报告像素／三维偏差分布与失配样例，验证深度毫米到米、位姿方向、图像旋转、裁剪与遮挡。阈值按图像分辨率和部位尺度在开发场景锁定。
- 输出：RGB／深度／mask 对照、点云 HTML 或轻量 PLY、对应误差表、每帧处理时间与内存。

**继续条件：**没有系统性镜像、尺度或坐标错位；关键部位在不同视图中对应合理。对齐失败先修数据，不启动模型训练。E0 通过只能说明工程链路可用。

### E1：冻结特征与小规模记忆读取

**问题：**有限历史特征能否帮助找回已见功能区域，是否存在可供训练的区域信号？

- 选择一个能输出局部 patch tokens 的小型公开编码器；首候选 DINOv2 ViT-S/14。确认许可证、权重入口及标准 PyTorch 推理可用后锁版本；使用标准 attention，首版避免强制 CUDA/xFormers 或稀疏卷积依赖。
- 原始帧保留用于投影和评估，模型输入先统一到合适的小分辨率；可从448边长试起。小部件丢失时只增加固定规则的局部高分辨率分支，各组一致使用，禁止用测试 GT 裁剪对象。
- batch=1、逐帧特征提取，优先实测 MPS，失败则 CPU。先测10–20帧，再外推，不预报真实运行时长。
- 特征一次缓存，训练 head 时读取缓存；Mac 上小 head 可以运行，但本周重点是数据和读取可用性，不要求取得跨场景训练结论。
- 在开发场景中用少量带标签局部特征建立原型或拟合小 head，在独立后续视图读取；清楚记录哪些标签被用于原型／拟合。测试视图及被读取的测试记忆内容不得输入 GT mask。
- 按视频时间前缀建记忆，之后的观察用作查询；不把未来观察倒写进较早记忆。先选择功能类型／示范区域查询，开放自然语言理解后接。
- 记录普通视觉历史记忆与当前帧的差异；前者比后者好，只证明历史有帮助，不证明新 affordance 算法有效。

**输出：**同一区域跨视角对应、历史来源帧、当前可见／当前不可见但历史已见／从未观察三类覆盖统计，以及记录时间和资源的实验页面。输出中区分训练内检查和独立视图诊断，不把同场景新视图称为未见场景泛化。

**最快可见结果：**在一个场景里，系统能从历史观察找回当前画面不包含的功能区域，并展示原始证据。真实数据若不可得，本周最多完成 UMD 局部检查，不冒充通过场景阶段。

## 4. 拿到 Isambard-AI 后的核心小训练

### E2：affordance 特征层是否有额外价值？

先固定一个受控规模：**12个物理场景，8训练／2验证／2最终pilot测试**，每场景抽取约80–120帧、每场景只用一段序列。场景须有可用人工标签，先检查选定功能类型在训练集的覆盖；划分和查询清单在看最终测试结果前锁定。若跨场景模型明显不收敛，先做小样本过拟合排错，不通过增加测试调参掩盖。

这属于自定义pilot划分，不是官方leaderboard结果；后续正式实验重新按官方协议设计。避免同一环境的其他扫描／视频落到不同集合。

**统一结构：**共享冻结视觉编码器；稀疏空间 patch 记忆；小型投影/上下文模块；同一种任务条件区域解码器。首版只训练新增模块，按实际特征保留局部隐式向量，map 只是监督／输出。

| 组别 | 内容 | 能回答什么 |
| --- | --- | --- |
| C0 当前帧 | 当前视觉特征，同一种区域解码任务 | 没有历史时的能力；信息量少，是诊断组 |
| C1 普通历史记忆 | 相同历史的普通视觉特征 | 历史本身的收益 |
| C2 参数匹配的额外视觉分支 | 与C3同参数、token、上下文和优化预算；辅助视觉目标 | 增加容量／训练是否已足够 |
| C3 Affordance 分支 | 额外分支使用训练集功能区域监督，保存map前特征 | affordance表征与监督组合的增益 |

各训练组的最终区域解码器使用相同训练标签。C3 的额外功能辅助损失是方法差异，C2 用相同标签数据训练共享任务并加视觉辅助目标；明确辅助监督内容并非完全相同，不能将C3收益全归因于某一个网络结构。

对C2/C3再各关闭历史读取一次。C3 若显示优势，再补“C2也用同样affordance辅助监督但不采用新写入/融合”的强对照，以区分标签、表征和记忆机制。首轮不要一次跑所有排列。

**主指标：**独立有效标注表面上的功能区域 mIoU，按场景等权汇总并分功能类别报告；先锁定阈值/忽略区域定义。使用可见性与点匹配将预测映射到参考扫描；未知区域不自动置负。额外报告历史覆盖比例，避免把没观察过的点当作记忆失败。

**辅助指标：**关键证据帧 Recall@3（标签由独立目标可见性／投影覆盖判定，允许多张正确帧）；当前视野缺失但历史已见区域的定位；存储字节、写入与读取延迟。首轮是区域／证据帧检索，不称为完成了交互视频迁移。

**工程继续门槛（预设建议）：**C3比C2主指标提高约5个百分点，并且两个测试场景的方向一致、没有明显靠丢弃难例换收益，值得扩大实验。先1个种子筛查，有信号再补至3个种子。小样本门槛不是统计显著性或泛化证明；1–2个百分点或场景方向相反先判不确定。C3只优于C0时，证据仅支持历史价值。

测试GT仅供评估；不可把测试场景GT map当记忆输入，也不可用同一教师伪标签作为唯一评估标准。模型预训练重叠若无法排除，应列为限制。

## 5. 可选 E3：环境与更新，分别验证

SceneFun3D 是静态场景调查，不提供完整交互过程，E2成功不代表理解障碍或动态环境。通过E2后才投入这一阶段。

- 固定对象和目标，控制一个障碍物／占用区域从空闲→占用→清空，建立30–50组配对布局作为数据生成pilot；真正训练所需数量在pilot后决定。
- 首先可测试几何空间／占用条件；标签来自明确定义的几何检查，只称几何兼容性。要测试推拉成功，需真实执行定义好的动作并记录位移、碰撞与结果。
- 相机先看见原状态，转开后回看变化，再测试旧证据撤销。未观察到的外部变化不能要求模型凭空知道。
- 同布局不同状态按完整组划分训练测试，保持对象外观相同以检验环境条件是否起作用。

ManiSkill/SAPIEN 是候选，但Isambard-AI是Linux aarch64，模拟器二进制与图形栈未验证。先确认包架构与离屏渲染支持；不把模拟器安装作为E0–E2前置条件，不承诺能在该平台直接pip安装。若原生不支持，另用可运行的渲染机器生成小数据再上传，或先采用解析几何测试。参考[官方安装文档](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/installation.html)。

## 6. Mac与远程职责、预算及可视化

| 工作 | 本周Mac M1/16GB | Isambard-AI |
| --- | --- | --- |
| 小样本检查、投影、实验页面 | 主要承担 | 可批量处理 |
| 冻结特征提取 | 10–20帧测速后，扩至每场景40–80帧 | 处理12场景及后续扩容 |
| 轻量head／adapter训练 | 可做小样本调试，按实测缩放 | E2主训练 |
| 数据存放 | 新增总量先限8GiB；只保留小样本、结果 | 原始序列、缓存、checkpoint |
| 可视化 | 浏览器打开PNG、MP4、HTML与下采样点云 | 无显示环境生成可视化文件 |

本地特征缓存的量级可计算：假定每帧1024个patch、384维、float16，则100帧约75MiB；这是给定张量形状的算术值，不包含模型、原图、点云、临时解压或训练激活，不是完整实验磁盘大小。小部位所需更高分辨率会增加成本。

Isambard-AI[官方规格](https://docs.isambard.ac.uk/specs/)为Grace Hopper、Linux aarch64、每GPU约96GB；实际分配及可用额度以账号为准。Mac和远程虽然都可能称arm64，但系统、加速后端和二进制不同，不能拷贝虚拟环境直接复用。

建议首轮申请总计**10–20 GPU小时的预留额度**作为规划上限，不是计算需求实测：先一次1GPU／30–60分钟环境与吞吐测试，再按测速分配特征缓存和各模型的1–2小时短作业；有有效结果才扩种子。单GPU优先，不因整节点有4卡就默认多卡。CPU内存、磁盘先依一个场景的峰值与包大小外推，并确认账户能否单卡调度、计费粒度和项目配额。

[官方运行教程](https://docs.isambard.ac.uk/user-documentation/tutorials/intro-tour/)支持通过Slurm申请单GPU；训练在计算作业中运行。[文件传输指南](https://docs.isambard.ac.uk/user-documentation/guides/file_transfer/local/)可用于取回结果。账号、project、partition/QoS、模块和联网权限未提供前，不编写假定可执行的队列参数。

输出页面应含：RGB视频及时间、二维预测/GT对照、带颜色的下采样三维区域、历史来源帧、C0/C2/C3并排比较、失败案例、资源表。远程保存metrics JSON/CSV、checkpoint和run manifest；Mac仅取图像、短视频和最多数万点的HTML/PLY，不在浏览器加载完整高精扫描。

## 7. 时间安排与继续／停止决策

| 阶段 | 主动工作安排目标（非实际耗时承诺） | 阶段结论 |
| --- | --- | --- |
| 本周第1个工作块 | 独立Python环境；数据体积盘点；1场景／10–20帧 | 是否能读取并正确对齐 |
| 第2个工作块 | E0与40–80帧缓存；统一输出页面 | 工程链路是否可用 |
| 第3个工作块 | E1历史读取与独立视图检查；锁E2划分和指标 | 是否已有可学习的区域信号 |
| 拿到远程后的第1个工作块 | aarch64环境、CUDA、单GPU及吞吐验证 | 确定真实作业预算 |
| 后续2–3个工作块 | E2的C1/C2/C3，先单种子后决定复验 | 是否值得继续训练此层 |

每个工作块可按半天到一天安排；下载、账号申请、排队与依赖故障不计入该目标，不承诺本周拿到方法有效性结论。

停止／调整规则：空间错位先修输入；oracle对齐好而预测差则查表征和监督；历史有效但C3无额外增益则不宣称新层有效；C3有信号但E3失败则将结论收窄为功能区域记忆。数据不足时增加合适场景，不通过测试调参维持正结果。

**第一项实际行动：先检查一个SceneFun3D序列包的大小与资产清单，并在隔离环境中读取10–20帧。所有数据下载、依赖安装、远程登录与计算作业仍待后续执行。**
